---
name: Cloudflare analytics workflow permissions
description: Permission boundaries and diagnosis for Cloudflare analytics and WAF audits.
---

Cloudflare GraphQL access is scoped by dataset and field: analytics read can allow `viewer.zones.firewallEventsAdaptive` and event metadata (`score_total`, `score_rules`), while `wafRequestSignatureCategories` / `wafRequestSignatureRefs` may remain unavailable even with analytics and WAF read scopes. In this environment, adding `Account WAF:Read` enabled zone/account ruleset detail and version reads; `Account Rulesets:Read` plus `Zone WAF:Read` alone returned 403. Managed ruleset responses expose IDs, refs, descriptions, and actions, but not expressions or matched variables. Map opaque `score_rules` values to the ruleset's `id` field at the event's `ruleset_version`.

**Why:** Schema introspection and access to event rows do not imply access to signature details or ruleset configuration. The event description `949110: Inbound Anomaly Score Exceeded` identifies the managed blocking threshold, not which underlying signature contributed the score; `score_rules` may contain opaque IDs. Rule descriptions can identify broad input classes, but not the exact cookie or JSON key without matched-variable data. `firewallEventsAdaptive` also rejects query windows wider than 4w3d.

**How to apply:** Keep audit credentials separate from deployment credentials and restrict them to the target zone plus its account-level ruleset resource. Verify each dataset with read-only calls, map `score_rules` against the historical ruleset version, and keep queries within 4w3d. If GraphQL signature fields remain denied, use redacted Security Events Additional logs for the matched variable/key. Do not bypass the threshold before identifying the contributing signatures and request field.
