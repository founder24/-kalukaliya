The six issues from v1 have all been addressed: `requirements-dev.in` now exists with the three test deps, CI installs test deps explicitly via `pip install pytest pytest-asyncio pytest-cov` rather than relying on the stale lockfile, TypeScript is corrected to `~5.8.3`, startup warnings fire when `ADMIN_JWT_SECRET` or `RESET_TOKEN_SECRET` are unset in production, dedicated rate limiter tests exercise the 503 and 429 paths, and bandit is consolidated into the shared `pip install ruff mypy bandit` line in the lint job.

## High-level view

All six v1 issues are resolved. The `requirements-dev.in` file was created and CI explicitly installs test deps in the test job rather than relying on the lockfile. The TypeScript version matches the spec at `~5.8.3`. The `config.py` validator now emits `logger.warning` for missing `ADMIN_JWT_SECRET` and `RESET_TOKEN_SECRET` in production mode, giving operators a clear signal. The rate limiter test file covers the 503 fail-closed path, the 429 exceeded path, and the happy path. Bandit is installed alongside ruff and mypy in the lint step, benefiting from pip caching.

The stale lockfile (`requirements.txt` still pinning pytest) is not a blocking issue because CI's test job now installs test deps explicitly. However, the lockfile remains out of sync with `requirements.in`, meaning a future `pip-compile` will produce a smaller lockfile and the Dockerfile (which installs from `requirements.txt`) currently ships test tooling into production. That's pre-existing technical debt rather than a regression from this PR.

## Stale docstring in the rate limiter

The `_check_rate_limit` function at `apps/backend/app/api/v1/auth.py:214` has this docstring:

```python
"""
IP-based rate limiting using Upstash Redis.
Raises HTTP 429 if limit exceeded. Silently skips if Redis unavailable.
"""
```

The "Silently skips" clause directly contradicts the implementation two lines below it which raises a 503. This is a documentation bug introduced by the fail-closed fix — the code was updated but the docstring wasn't. Low severity, but a future reader will be confused about the intended behavior.
