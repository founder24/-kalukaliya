# Removal of invalid Vite 7 configuration keys

The change strips two configuration blocks from `apps/frontend/vite.config.js` that are not recognized by Vite 7.3.3: a top-level `oxc` key (likely targeting a rolldown-based Vite beta that exposed oxc transform options at the root) and an `optimizeDeps.rolldownOptions` key (not part of Vite 7's `DepOptimizationConfig`). Both were silently ignored at runtime but represented dead configuration that could mislead future contributors. The react() plugin with `include: /\.(js|jsx|ts|tsx)$/` already handles JSX transformation for source files.

**Watch for:** Nothing blocking. The change is purely subtractive, removing code that had no runtime effect (confirmed). The only consideration is whether the config was forward-looking (targeting an unreleased Vite version) and might need to be re-added later.

**Verdict**: APPROVED

## High-level view

The `oxc` block declared JSX transform settings (automatic runtime, react import source) that overlap entirely with what `@vitejs/plugin-react` already provides via the `include` pattern. Since Vite 7 doesn't expose an `oxc` config key at the `UserConfig` level, the block was inert. Removing it eliminates confusion about which mechanism handles JSX.

The `rolldownOptions.moduleTypes` entry inside `optimizeDeps` aimed to tell the bundler to treat `.js` files as JSX during dependency pre-bundling. Vite 7 uses esbuild for dep optimization and does not support this key; the react plugin's `include` regex handles JSX-in-JS files during serve and build. Removing it aligns the config with what Vite actually reads.

## Dead configuration from a rolldown-native Vite variant

The `oxc` block (`include`, `exclude`, `lang`, `jsx.runtime`, `jsx.importSource`) mirrors the configuration surface that appeared in rolldown-vite (the experimental Vite fork using rolldown as the bundler). In that variant, top-level `oxc` configures the oxc-based JS transform that replaces esbuild. In stock Vite 7.3.3 with `@vitejs/plugin-react`, these settings have no consumer — the plugin internally configures Babel (or SWC, depending on variant) for JSX. The removal is confirmed correct by a passing build and 623 tests.

Similarly, `optimizeDeps.rolldownOptions` is a rolldown-vite concept where the optimizer accepts rolldown-native module type mappings. Stock Vite 7 pre-bundles with esbuild and exposes `optimizeDeps.esbuildOptions` instead. The removed `{ moduleTypes: { '.js': 'jsx' } }` had no effect; esbuild's JSX handling for dep pre-bundling is controlled elsewhere (and isn't needed here because `.js` files in `node_modules` that contain JSX are rare — the `include` list pre-bundles react itself which ships CJS, not JSX).
