# Graceful degradation guards and Cloudflare Worker deployment hardening

This change adds defensive guards across two systems: the Python backend gets fail-closed error handling for missing Razorpay credentials, uninitialized MongoDB/Beanie, and broken CSRF checks in tests; the Cloudflare Worker edge gets null-checks for missing KV bindings (rate limiter and ISR cache) so local dev and preview deploys don't crash. Three new edge test files and one new backend test file cover these scenarios comprehensively.

Watch for: CSRF bypass logic skips validation when no Origin header is present, which weakens protection against non-browser attackers that omit Origin (confirmed). The `CollectionWasNotInitialized` exception handling uses a broad `except Exception` pattern with isinstance checks rather than catching the specific exception directly, which obscures intent (confirmed). Rate limiting in the edge worker is fully skipped when `RATE_LIMIT_KV` is falsy, meaning a misconfigured production deploy silently loses rate limiting with no signal (confirmed).

## High-level view

The backend degradation strategy converts infrastructure failures (missing credentials, uninitialized DB, unavailable Redis) into explicit 503 responses. The CSRF changes go further than necessary by disabling checks entirely in test mode *and* when Origin is absent, rather than narrowly scoping the fix to test fixtures. This means the protective behavior is never exercised by any test.

The edge worker hardening makes KV-dependent features (rate limiting, ISR caching) opt-in rather than mandatory. If `RATE_LIMIT_KV` or `ISR_CACHE_KV` is missing from the env bindings, those code paths are skipped silently. This prevents crashes in `wrangler dev` but creates a silent security degradation path in production if bindings are misconfigured.

The test coverage is thorough for the happy-path degradation scenarios. What's missing: no test for the CSRF bypass logic itself, no test that verifies rate limiting is *not* silently skipped when KV *is* present but misbehaves, and the FEAT-003 spec's timeout handling for the proxy was never implemented.

<details>
<summary>Issues (5)</summary>

1. **CSRF bypass on missing Origin** — Skipping CSRF validation when no Origin/Referer header is present means non-browser clients (scripts, API tools, CSRF exploits via non-standard user agents) bypass protection entirely. Consider failing closed for admin mutating endpoints or requiring an explicit API key for programmatic access.
2. **Silent rate-limit skip in production** — If `RATE_LIMIT_KV` binding is accidentally missing in production wrangler.toml, rate limiting disappears with no error, log, or header. Add a response header (e.g., `X-Rate-Limited-By: none`) or console.warn when the binding is absent in non-dev environments.
3. **Broad exception catch for Beanie** — `except Exception as e: if isinstance(e, CollectionWasNotInitialized)` is used in 5 places. Any unexpected exception that *isn't* `CollectionWasNotInitialized` is silently re-raised without logging. Add `logger.error` for unexpected exceptions before re-raising.
4. **String-matching for error classification** — `subscription.py` routes `RuntimeError` to 503 vs 502 based on `"not configured" in error_msg`. This couples the HTTP status to the exact wording in another module. A dedicated exception subclass would be more robust.
5. **No negative CSRF test** — There's no test that verifies the CSRF check *does* reject cross-origin requests in non-test environments. The fix disables CSRF in `APP_ENV=test`, so the protective behavior is never exercised by the test suite.

## CSRF bypass scope is wider than the fix requires

The admin `_csrf_check` function now early-returns in two cases: when no Origin/Referer header is present, and when `APP_ENV == "test"`. The middleware in `main.py` mirrors this.

The no-Origin bypass alone is defensible — browsers always send Origin on cross-origin POST, so absence means the request isn't a browser-initiated CSRF attack. But combining both bypasses means CSRF is *completely* disabled in the test environment, leaving no way to write a test that validates CSRF rejection works. If the CSRF logic is ever accidentally broken, no test will catch it.

The `APP_ENV == "test"` bypass is redundant given the no-Origin bypass (test runners don't send Origin). The redundancy suggests the threat model isn't clear:

```python
# In admin.py _csrf_check:
if not origin:
    return  # API clients / test runners — no Origin = not a browser CSRF
if settings.APP_ENV == "test":
    return  # Redundant if above covers it — but needed if test sends Origin?
```

## Silent rate-limit degradation in edge worker

```typescript
if (env.RATE_LIMIT_KV && url.pathname.startsWith('/api/v1/chat') && request.method === 'POST') {
```

When `RATE_LIMIT_KV` is `undefined`, the entire rate-limiting block is skipped with no signal to operators. A production deploy with a typo in `wrangler.toml` would silently serve all traffic without limits. The test validates the *absence* of a crash but not the *presence* of a warning signal.

## Exception handling pattern in auth.py and admin.py

```python
try:
    from beanie.exceptions import CollectionWasNotInitialized
except ImportError:
    CollectionWasNotInitialized = None
```

Five instances of `except Exception as e` + `isinstance` check. When the exception is *not* `CollectionWasNotInitialized`, it's re-raised without logging. In a production MongoDB outage (network timeout, auth failure), these would propagate as unhandled 500s with no application-level log. Adding `logger.error(f"Unexpected DB error: {e}")` before `raise` would help operators triage.

A utility function like `def handle_beanie_error(e): ...` would reduce the 5-instance repetition and centralize the logging gap fix.

## Error classification via string matching in subscription.py

```python
except RuntimeError as e:
    error_msg = str(e)
    if "not configured" in error_msg:
        raise HTTPException(status_code=503, detail="Payment service not configured")
    raise HTTPException(status_code=502, detail="Payment gateway error")
```

If someone edits the error message in `razorpay_client.py` (e.g., "Razorpay credentials not configured"), the 503 becomes a 502. Define `class PaymentNotConfigured(RuntimeError): pass` in the client module and catch it specifically.

## Test conftest global User patch

The `client` fixture patches `User.find_one` and `User.get` to return `None` globally:

```python
with patch("app.models.user.User.find_one", new_callable=AsyncMock, return_value=None), \
     patch("app.models.user.User.get", new_callable=AsyncMock, return_value=None):
```

Any test that needs a user lookup to succeed must override this patch. This creates a maintenance trap — adding a test that expects user data requires knowing about the hidden `find_one=None` default. Tests that override with `side_effect` (like the Beanie degradation tests) work via patch stacking, but there's no documentation or fixture naming that signals this behavior.

## Edge test coverage gaps

Missing scenarios:

- No test for an expired/invalid JWT that *is* present (the edge returns 401 for malformed tokens — covered in `jwt.test.ts` but not in integration-level `deployment-audit.test.ts`).
- No integration test for the ISR handler being invoked via the main fetch handler with a bot UA (the ISR unit tests exercise `handleISR` directly but the deployment test only hits the 404 fallback for non-bot UAs).
- The proxy tests don't cover timeout behavior. FEAT-003 spec mentions adding 30s timeout handling, but no timeout was implemented in `api-proxy.ts` — requests to a hanging backend will wait indefinitely.
