Syrabit Admin Panel — Full Upgrade Plan
What the Audit Found (Problems to Fix)
Code size problem — two monolith files dominate the panel:
AdminDashboard.jsx — 5,663 lines, 8 KPI fields returning {"source":"placeholder"}
AdminHealth.jsx — 4,971 lines, dozens of widgets crammed into one file
Analytics section is almost completely fake:
10 of 11 analytics endpoints return hardcoded zeros — the entire analytics section renders empty charts
Auth is inconsistent across routers:
admin_dashboard.py — uses clean router-level Depends(require_admin_session, csrf_guard) ✅
admin_analytics.py, admin_ai.py, admin_translate.py, admin_users.py, admin_conversations.py, admin_notifications.py, admin_revenue.py — all use inline _validate_admin_session() with no CSRF protection ❌
Frontend calls non-existent backend routes:
GET /admin/analytics/funnel → 404
GET /admin/analytics/content-heatmap → 404
Duplicate routes:
/admin/cf-overview exists in both admin_dashboard.py and admin_analytics.py, both returning zeros
/admin/health in admin_dashboard.py duplicates /health/deep from health.py
The core architectural problem (from your plan doc):
AdminContentHub mixes three completely different concerns with no visual or code separation:
Page-view content (notes/MCQs shown to students) → should live in CF KV / R2
RAG retrieval chunks (text for AI context) → lives in MongoDB chunks + Vectorize
EN→AS translation pipeline → completely different workflow
AI Hub only shows Sarvam — Gemini/Vertex AI and CF Workers AI are completely absent from the providers panel despite being the actual models serving production traffic.
Architecture Decisions
Storage rule — one source of truth per data type:
Data typeStorageServe path
Student page views (notes, MCQs, summary)
CF KV CONTENT_KV + R2
Edge-served, zero backend dependency
Curriculum metadata (boards/classes/subjects/chapters)
MongoDB
Backend is source, CF KV is read cache
RAG retrieval chunks
MongoDB chunks + CF Vectorize
Backend for write, Vectorize for retrieval
AI generation jobs
MongoDB generation_jobs
Backend tracks, admin polls
Translation status
app.state in-memory
Ephemeral — jobs are short-lived, acceptable
