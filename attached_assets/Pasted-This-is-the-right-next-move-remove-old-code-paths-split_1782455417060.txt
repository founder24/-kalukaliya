## Recommended split
- **Content Editor:** keeps the current frontend content structure; page-view data is stored on Cloudflare and served directly, with no backend dependency for browsing. [developers.cloudflare](https://developers.cloudflare.com/cloudflare-for-platforms/workers-for-platforms/configuration/static-assets/)
- **RAG Editor:** a new panel that looks like the content editor but stores structured **JSON RAG data** only, for ingestion into MongoDB chunks and Cloudflare Vectorize. [developers.cloudflare](https://developers.cloudflare.com/vectorize/reference/metadata-filtering/)

## What to remove
- Old duplicated editor logic.
- Legacy RAG code paths that bypass the new schema.
- Any page-view flow that still reads from backend tables when Cloudflare static assets should serve it directly. [github](https://github.com/cloudflare/cloudflare-docs/blob/production/content/pages/tutorials/use-r2-as-static-asset-storage-for-pages/index.md)

## New storage rule
- **Frontend page views:** Cloudflare static assets / page assets.
- **Editable content metadata:** MongoDB.
- **RAG JSON payloads:** MongoDB + Vectorize metadata/embeddings. [developers.cloudflare](https://developers.cloudflare.com/vectorize/reference/client-api/)
