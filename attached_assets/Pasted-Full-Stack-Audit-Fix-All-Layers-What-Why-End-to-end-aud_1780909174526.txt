Action 3.5 — Fix GitHub secret encryption method (libsodium, not RSA)

GitHub's Secrets REST API (PUT /repos/{owner}/{repo}/actions/secrets/{name}) requires the secret value to be encrypted with the repo's libsodium public key using crypto_box_seal (NaCl sealed box). This is NOT RSA encryption.

Any infra script that uses RSA to encrypt before PUT will produce an unusable encrypted value — GitHub silently stores it, but the Actions runner fails to decrypt and injects an empty string.

Correct implementation:

// infra/scripts/set-github-secret.js
const sodium = require('libsodium-wrappers');
const fetch = require('node-fetch');
async function setGitHubSecret(repo, token, secretName, secretValue) {
  await sodium.ready;
  
  // Step 1: Get repo public key
  const keyRes = await fetch(
    `https://api.github.com/repos/${repo}/actions/secrets/public-key`,
    { headers: { Authorization: `Bearer ${token}`, Accept: 'application/vnd.github+json' } }
  );
  const { key, key_id } = await keyRes.json();
  // Step 2: Encrypt with libsodium sealed box (NOT RSA)
  const publicKey = sodium.from_base64(key, sodium.base64_variants.ORIGINAL);
  const messageBytes = sodium.from_string(secretValue);
  const encryptedBytes = sodium.crypto_box_seal(messageBytes, publicKey);
  const encryptedValue = sodium.to_base64(encryptedBytes, sodium.base64_variants.ORIGINAL);
  // Step 3: PUT to GitHub API
  const putRes = await fetch(
    `https://api.github.com/repos/${repo}/actions/secrets/${secretName}`,
    {
      method: 'PUT',
      headers: {
        Authorization: `Bearer ${token}`,
        Accept: 'application/vnd.github+json',
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({ encrypted_value: encryptedValue, key_id }),
    }
  );
  // HTTP 201 = created, 204 = updated. Both are success.
  return putRes.status; // should be 201 or 204
}

Install dependency: npm install libsodium-wrappers node-fetch in infra/scripts/.

⚠️ False positive: GitHub PUT returns HTTP 204 (No Content) on success for updates. An empty response body does NOT mean failure. echo $? after curl returning 204 will be exit code 0.

def decode_token(token: str) -> dict:
    """Decode a JWT token — tries HS256 first, falls back to RS256 for legacy tokens."""
    errors = []
    for alg in ["HS256", "RS256"]:
        try:
            if alg == "HS256":
                return jwt.decode(
                    token,
                    settings.JWT_SECRET,
                    algorithms=["HS256"],
                    options={"verify_exp": True}
                )
            else:

                if not settings.JWT_PUBLIC_KEY:
                    continue
                return jwt.decode(
                    token,
                    settings.JWT_PUBLIC_KEY,
                    algorithms=["RS256"],
                    options={"verify_exp": True}
                )
        except Exception as e:
            errors.append(f"{alg}: {e}")
    raise ValueError(f"Token decode failed: {errors}")

Fix A — add exponential backoff to embedding calls in mongo_vector_search.py:

import asyncio
from google.api_core.exceptions import ResourceExhausted
async def _get_embedding_with_retry(text: str, max_retries: int = 3) -> list[float]:
    """Get text embedding with exponential backoff on 429."""
    for attempt in range(max_retries):
        try:
            return await _get_embedding(text)
        except ResourceExhausted as e:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt  # 1s, 2s, 4s
            logger.warning(f"Embedding rate limited (attempt {attempt+1}), retrying in {wait}s")
            await asyncio.sleep(wait)
        except Exception:
            raise
