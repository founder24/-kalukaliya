Root Cause Audit — [LLM error — please retry. (HTTPStatusError)]
What happened
The production app at syrabit.ai runs the ACA backend, which has CF_AI_GATEWAY_ID = "syrabit" set in its Azure environment (hardcoded in infra/azure/aca-syrabit-backend.bicep). The Replit dev server does not have this variable set.

Because of that single env var difference, the two environments route Workers AI traffic to completely different URLs:

Env	CF_AI_GATEWAY_ID	URL used
Dev (Replit)	(empty)	api.cloudflare.com/…/ai/run/{model} ✅ always works
Prod (ACA)	syrabit	gateway.ai.cloudflare.com/v1/{account}/syrabit/workers-ai/{model}
The gateway is an authenticated endpoint — it requires a matching cf-aig-authorization: Bearer <token> header. That token comes from the CF-AI-GATEWAY-TOKEN secret in Azure Key Vault. If that secret drifted out of sync with the current CLOUDFLARE_API_TOKEN (e.g. after a token rotation, or the Key Vault secret wasn't updated), the gateway returns HTTP 401/403, which httpx.HTTPStatusError surfaces, and the chat handler catches and streams to the browser as the error message you saw.

Why it was invisible in dev
The dev server never goes through the gateway, so the token mismatch never triggered. The call hit the direct Workers AI API which worked fine.

Three fixes applied
providers/cloudflare_ai.py — gateway-auth fallback (_post and chat_stream): if the CF AI Gateway returns 401 or 403, the code now automatically retries the same request against the direct Workers AI API (api.cloudflare.com) with only the Authorization header. This means a stale gateway token no longer kills chat — it degrades gracefully to direct mode and logs a warning.

providers/cloudflare_ai.py — header hygiene (_headers): the cf-aig-authorization and cf-aig-cache-ttl headers are now only sent when actually routing through the gateway. Sending them to the direct API was harmless today but could cause routing confusion in edge cases.

routes/ai_chat_direct.py — human-readable errors: the exception handler now checks the HTTP status code and shows:

429 → "Service is busy right now — please try again in a moment."
401/403 → "AI service authentication error — please contact support."
other 4xx/5xx → "AI service returned HTTP NNN — please retry."
No more raw Python exception type names leaking into the chat UI.

To permanently fix production
Ensure the CF-AI-GATEWAY-TOKEN secret in Azure Key Vault matches the current CLOUDFLARE_API_TOKEN. The Bicep comment describes them as the same value — if the API token was rotated without updating the Key Vault secret, update it there and ACA will pick it up on the next revision.
