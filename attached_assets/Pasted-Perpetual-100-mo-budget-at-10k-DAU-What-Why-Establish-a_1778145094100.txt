Perpetual $100/mo budget at 10k DAU
What & Why
Establish a perpetual (post-credits) monthly spend ceiling of $100 USD across all clouds + specialists at 10k DAU, building on Task #513's caps + telemetry. This task adds the three founder decisions that #513 does not address:

Perpetual $100 cap — tighten #513's MONTHLY_TOTAL_USD_CAP from $500 to $100 and harden the auto-throttle so the cap holds even after Azure / GCP / Mongo / Pinecone credits expire.
Voice features → paid users only — gate /api/voice/* (TTS/STT/two-leg) behind an active Razorpay plan. Free users see an upgrade prompt instead of a 500. Removes ~$130–510/mo of ElevenLabs + Google TTS + Deepgram cost from the free tier.
Chat dispatch reorder with credit-runway-aware primary selection — promote Vertex Gemini Flash to primary chat (drains the $2k GCP credit pool first), demote Azure gpt-4.1-nano to paid-tier-only. When the Vertex credit pool drops below 90 days of runway at current burn, the dispatcher auto-promotes Workers-AI Llama to primary so the $100 ceiling holds perpetually without manual intervention.
This is a deliberate amendment to V4 §0 (cost split was 40/30/20/10) and the Task #494 chat-primary lock. The perpetual ceiling means the cost split shifts toward Cloudflare-heavy (Workers AI eventually carries primary chat) and GCP-during-credits — Azure is reduced to the paid-user fallback path.

Done looks like
A. $100 monthly hard ceiling, perpetual
MONTHLY_TOTAL_USD_CAP env default lowered from $500 → $100, documented in replit.md and the Bicep template.
The Rule D auto-throttle from #513 is hardened with a three-stage degradation ladder based on month-to-date spend:
$60 month-to-date (60 %) — tier-router pinned to "cheap-only" (Workers AI for all free chat); non-critical batch jobs (SEO, link-checker, indexing reconciliation) paused; admin alert fires.
$80 month-to-date (80 %) — voice disabled for everyone (including paid); content formatter falls back to Workers-AI Llama-3.3-70b only (Vertex skipped); page-cache TTLs doubled to reduce origin hits; admin pager fires.
$95 month-to-date (95 %) — chat returns 503 with error="monthly_budget_exhausted" for free users; paid users only; new free-tier signups disabled until month rollover; founder pager + email fires.
All three stages auto-clear at UTC month rollover. A manual override endpoint (POST /admin/budget/override, admin-only, audit-logged) lets ops reset a stage early during an incident.
B. Voice features → paid-users-only
routes/voice.py adds a require_paid_plan dependency on every endpoint (/api/voice/tts, /api/voice/stt, /api/voice/voice, /api/voice/health stays public). Free users get HTTP 402 with {"error":"voice_requires_paid_plan","upgrade_url":"/pricing"}.
Frontend voice entry-points (any "speak" button, voice-input mic, audio narration toggle on chapter pages) check the user's plan from the existing JWT claim and render a "Voice is a paid feature — upgrade to Plus" CTA instead of the active button when the user is on free.
The pricing page (/pricing) gains a "Voice & narration" line item under the paid plan.
A Sentry alert fires if voice-route 402-rate exceeds 0.5 % of total voice traffic for >24 h (signals a frontend regression where the gate isn't being respected client-side).
C. Chat dispatch reorder with credit-runway-aware primary
PROVIDER_PRIORITY["english_rag_chat"] reordered:
Position 1 (primary, while GCP credit > 90d runway): vertex_gemini_flash (gemini-2.5-flash)
Position 1 (primary, when GCP credit ≤ 90d runway): workers_ai (Llama-3.2-3B-Instruct)
Position 2: the other of the above two (whichever isn't primary)
Position 3: azure_openai (gpt-4.1-nano) — paid-user-only, never selected for free users regardless of position
Position 4: workers_ai (Mistral-7B-Instruct) — final fallback
The "credit-runway-aware" switch lives in llm.py::_select_chat_primary() and reads from the existing PROVIDER_CREDITS-driven runway calculator (already built in #513's Rule D foundation). It checks runway at every chat dispatch (cheap O(1) read from a 60s-cached value).
The locked test tests/test_provider_priority_locked.py::test_english_rag_chat_priority_locked is updated to assert the new order. A second test, test_chat_primary_flips_on_credit_exhaustion, simulates GCP credit dropping below 90d runway and asserts the dispatcher selects Workers AI Llama.
Update replit.md "Architecture decisions" §3 (chat dispatch) with the new chain + the credit-runway flip rule, and add an ADR at docs/architecture/adr/0002-perpetual-100usd-budget.md documenting the V4 §0 cost-split amendment.
D. MongoDB Atlas right-size + post-credit replacement plan
Audit current Atlas tier; downsize to M10 (~$60/mo cash, the smallest tier with replication + SLA) if currently larger. M10 alone consumes ~60 % of the $100 budget — this is the structural floor for the database.
Document a written post-Mongo-credit replacement evaluation memo at artifacts/syrabit/docs/infra/mongo-replacement-eval.md comparing three options to be exercised when Mongo credit drops below 6 months runway:
(i) Stay on M10 ($60/mo cash, no migration risk)
(ii) Migrate hot read paths to Cloudflare D1 + KV (D1 is on the existing 40 % CF allocation; would free ~$50/mo)
(iii) Self-host MongoDB on a single Hetzner / OVH VM (~$10/mo cash, but takes ops on)
The memo is written, not executed — execution is a separate task triggered by the credit-runway alert.
E. Pinecone Starter-tier feasibility audit
Audit current Pinecone usage: total vector count, monthly query count, monthly upsert count, total rerank-ops/mo. Compare against Pinecone Starter free-tier limits.
If usage fits Starter limits with ≥30 % headroom, migrate to Starter (saves ~$80–150/mo cash).
If rerank-ops are the bottleneck, evaluate replacing Pinecone rerank with Workers-AI rerank model (@cf/baai/bge-reranker-base) inline in the existing vectorless+vector fusion step. Document the quality delta on a 200-query rerank eval set.
Decision + migration plan land in artifacts/syrabit/docs/infra/pinecone-tier-decision.md.
F. Sentry cost cut
Audit Sentry monthly event/transaction volume; current paid tier ($80–150/mo) is incompatible with the $100 budget.
Implement one of:
(i) Drop to Sentry Developer free tier (5k errors + 10k transactions/mo) by tightening traces_sample_rate to 0.05 and adding before_send filters that drop noisy non-actionable events (third-party script errors, cancelled fetches, expected 4xx responses).
(ii) Stand up self-hosted GlitchTip on a Hetzner VM (~$5/mo cash) for errors and keep GCP Cloud Trace (free tier) for traces. GlitchTip is Sentry-SDK-compatible so no client code changes.
Recommendation goes to founder; one of the two ships in this task.
G. Email cost cut + Cloudflare Email Workers evaluation
Audit current SES volume. Apply hard caps in the email service: at most 3 transactional emails per user per day, batched daily digest for non-urgent notifications (replaces N individual sends with 1 digest).
Evaluate moving non-transactional notifications (digest, weekly summary, marketing) to Cloudflare Email Workers (free outbound via Resend-style routing, on the CF allocation). SES retained for password-reset / payment-confirmation only.
Target: SES cost from $40/mo → ≤$10/mo.
