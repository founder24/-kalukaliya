For Syrabit, the goal is NOT:

“make heavy free users cheap at any cost.”

The real goal is:

keep heavy free users economically bounded while preserving learning quality.

Your current architecture is already strong, but here’s the optimal layered minimization strategy for:

users who consume all 30 free chats/month.
🎯 Target

Current heavy free user cost:

~₹2–₹8/month

You can realistically push this toward:

~₹0.50–₹3/month

WITHOUT damaging UX too much.

🧠 Core Principle

Heavy educational traffic is:

repetitive,
syllabus-bound,
predictable,
cacheable.

So the strategy is:

progressively convert “chat” into “retrieval.”
✅ LAYER 1 — Hard Model Delegation

(Most important)

Free-tier users should NEVER hit expensive reasoning models unless absolutely necessary.

Recommended Free-Tier Routing
Query Type	Model
Definitions	KV cache only
MCQs	KV/prewarmed
PYQ explanation	KV + Workers AI
Basic Q&A	Workers AI Llama 3.2
Assamese basic	Sarvam small
Long reasoning	limited
OCR	quota-limited
Voice	disabled/free preview only
🔥 Biggest Optimization
Vertex Gemini should almost disappear for free users.

Use it ONLY for:

premium users,
formatter fallback,
complex reasoning escalation.

This alone massively cuts cost.

✅ LAYER 4 — Progressive Degradation for Free Users

VERY important.

Not all chats deserve equal compute.

Suggested Free-Tier Policy
Usage State	Behavior
First 10 chats	normal
10–20 chats	smaller models
20–30 chats	cache-first + strict retrieval
>30	paywall

This is MUCH better than:

abrupt blocking,
or expensive unlimited inference.
⚡ At 20–30 Chats

Switch strategy to:

retrieval-heavy mode.

Meaning:

shorter outputs,
precomputed educational snippets,
aggressive cache reuse,
no premium formatting.

Students still learn effectively.

✅ LAYER 5 — Retrieval-First Chat

Critical.

Before ANY LLM call:

search:

KV cache,
D1 syllabus,
MCQ cache,
PYQ cache,
prewarmed content.

If confidence high:

skip inference entirely.
🧠 Education Is Ideal For This

Unlike general chatbots,
education has:

finite syllabus,
repetitive concepts,
constrained domain.

This makes retrieval-first extremely effective.

Goal:

Sarvam only for high-value Assamese reasoning.

This dramatically reduces:

latency.

(#574)
