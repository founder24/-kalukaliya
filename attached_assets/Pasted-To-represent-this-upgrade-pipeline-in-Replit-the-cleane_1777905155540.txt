To represent this **“upgrade pipeline”** in Replit, the cleanest way is to:

1. **Write three follow‑on task‑sketches** into files like `wip/roadmap-perf.md`, `wip/roadmap-features.md`, `wip/roadmap-capacity.md`, and  
2. **Accompany them with a small shell reminder** so you can run a quick `cat` / `edit` workflow.

Below are **ready‑to‑paste Replit‑style commands and file contents** you can drop into your project.

***

### 📂 Step 1 — Create roadmap files

Run these in the Replit shell:

```bash
mkdir -p wip
```

Then create three files:

#### 1. `wip/roadmap-perf.md` — Perf‑wishlist follow‑on

```bash
cat > wip/roadmap-perf.md << 'EOF'
# Perf follow-on task (post #359/#360)

## Goal
Improve chat‑TTFB and effective RAG‑capacity using caching, model‑choice A/B, and real‑p99 measurement.

## Work items
- [ ] Add RAG‑result cache:
    - Redis key: `rag:query_hash:<hash>` → (RAG‑chunks + LLM‑answer, TTL).
    - Only hit when:
        - query is “stable” (no attachments, no ephemeral‑hints),
        - syllabus‑version is current.
- [ ] Add embedding‑cache for repeated questions:
    - Redis key: `embed:question:<hash>` → embedding vector.
    - Use when same‑chapter‑or‑topic‑question repeats.
- [ ] A/B test `llama‑3.2‑1b‑instruct` vs `3b‑instruct` in `fast_mode`:
    - Log:
        - TTFB,
        - cost‑per‑turn,
        - user‑rating / engagement.
    - Gate promotion behind non‑negative‑quality‑delta.
- [ ] Instrument real‑world p99:
    - Export TTFB / RAG‑latency to App Insights / CloudWatch.
    - Identify long‑history / stuck‑session outliers and add:
        - history‑truncation,
        - chunk‑rank‑re‑ordering,
        - per‑turn‑history‑budget.

## Target SLO delta vs baseline
- Blended TTFB p50: ~400–600 ms (down from ~600–900 ms).
- Effective daily RAG capacity: ~12–15k turns/day at same quota.
EOF
```

#### 2. `wip/roadmap-features.md` — Features wishlist

```bash
cat > wip/roadmap-features.md << 'EOF'
# Features follow-on task (post #359/#360)

## Goal
Deepen memory‑brain recall, enable mixed‑language, and add smarter per‑session model‑fallback.

## Work items
- [ ] Long‑term‑summary embedding for full‑conversation recall:
    - Compute a conversation‑summary embedding every N new turns.
    - Store in Pinecone / Redis.
    - Use when user‑prompt scores high on “recall‑intent” (classifier / heuristic).
- [ ] Mixed‑language queries (Eng‑Q → Assamese‑A):
    - Route via `@cf/ai4bharat/indictrans2-en-indic-1b` + Sarvam‑M.
    - Measure end‑to‑end UX, not just translation BLEU.
- [ ] Per‑session multi‑model‑fallback:
    - If Mistral‑turns are stuck (slow‑TTFB for multiple turns),  
      flip that session to `Azure‑GPT‑4.1‑mini` via a Redis‑hash‑per‑session.
- [ ] Friendlier moderation‑UX + safe‑/challenge‑mode:
    - Soft‑block messages with hints.
    - Add UI‑flags for stricter‑/looser‑moderation.

## Target SLO delta vs baseline
- p95–p99 tail tightens significantly (no more 3–8 s stuck‑sessions).
- p50 TTFB roughly unchanged or slightly better.
EOF
```

#### 3. `wip/roadmap-capacity.md` — Capacity scaling

```bash
cat > wip/roadmap-capacity.md << 'EOF'
# Capacity follow-on task (post #359/#360)

## Goal
Scale Syrabit to 500k–1M DAU without architectural rewrite.

## Work items
- [ ] Workers‑AI quota‑tier upgrade:
    - Move from current tier to higher‑paid‑tier.
    - Adjust Meter‑C thresholds accordingly.
- [ ] Add Vertex‑Gemini as partial‑hot‑path co‑primary:
    - Implement routing policy:
        - round‑robin,
        - sticky‑by‑session,
        - or quality‑weighted.
- [ ] Shard MongoDB by `user_id` or `locale`:
    - When single‑replica‑QPS approaches ceiling (~5–10k).
- [ ] Multi‑Redis‑node sharding:
    - For hot‑keys like `chat:fallback`, `chat:fallback:pin`.
- [ ] Async‑batch on separate CF/Azure account:
    - PDF‑summary / model‑paper‑generation on separate quota.

## Target SLO delta vs baseline
- Daily RAG ceiling: 10×–100× current.
- DAU envelope: ~500k–1M DAU comfortable.
EOF
```

### 🖥️ Shell command to “verify / inspect upgrade plan”

You can quickly **review** the entire upgrade roadmap:

```bash
cat wip/roadmap-perf.md
cat wip/roadmap-features.md
cat wip/roadmap-capacity.md
```

Or, if you prefer a **one‑liner reminder**:

```bash
echo "Perf, Features, Capacity upgrade roadmap:"
echo "  - Perf: caching + 1b/3b A/B + p99 tuning"
echo "  - Features: deep‑recall + mixed‑language + smart‑model‑fallback"
echo "  - Capacity: quota‑upgrades + sharding + multi‑account‑batch"
cat wip/roadmap-*.md
```
