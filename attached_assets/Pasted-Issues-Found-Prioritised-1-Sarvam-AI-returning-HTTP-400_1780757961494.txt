🔴 1. Sarvam AI returning HTTP 400 — Assamese chat degraded
Every Assamese (lang=as) request hits Sarvam, gets HTTP 400, then falls back to Gemini. Assamese users get answers but from the wrong model — Gemini responds in Assamese but with less cultural/linguistic precision than Sarvam. The circuit breaker will trip after 5 failures and stop trying for 60s.

The Sarvam API itself returns 403 for unauthenticated requests (correct), which means the key is valid — the 400 is a bad request format. Sarvam's sarvam-m model likely changed its accepted payload (model name renamed, or max_tokens → max_completion_tokens, or system role not supported).

Fix: Update the Sarvam model name or request payload. I can check their current API docs and patch sarvam_client.py.
