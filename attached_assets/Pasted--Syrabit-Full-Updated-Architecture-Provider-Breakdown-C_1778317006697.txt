# Syrabit — Full Updated Architecture, Provider Breakdown & Cache Optimization Blueprint (2026)

# 1. Vision

Syrabit is designed as:

```text
AI-native educational infrastructure
```

rather than:

```text
a generic chatbot
```

Core philosophy:

* retrieval dominates inference,
* curriculum constrains entropy,
* repeated outputs become infrastructure,
* edge materialization compounds over time,
* multilingual educational AI needs provider specialization.

---

# 2. Core Architectural Principles

| Principle                        | Why It Matters                        |
| -------------------------------- | ------------------------------------- |
| Edge-first delivery              | Reduce latency + backend cost         |
| Retrieval-heavy AI               | Minimize inference dependency         |
| Deterministic caching            | Turn repeated questions into assets   |
| Multi-provider orchestration     | Avoid lock-in + optimize quality/cost |
| Curriculum grounding             | Reduce hallucinations                 |
| Progressive degradation          | Sustain free-tier economics           |
| Materialized educational outputs | Compound over time                    |
| SEO-driven distribution          | Acquire users cheaply                 |

# 4. Multi-Cloud Infrastructure Breakdown

# 4.1 Cloudflare Layer (Primary Edge Infrastructure)

## Responsibilities

| Service          | Responsibility                 |
| ---------------- | ------------------------------ |
| Cloudflare Pages | PWA hosting                    |
| Workers          | edge compute                   |
| CDN              | global caching                 |
| KV               | deterministic AI cache         |
| D1               | syllabus graph + metadata      |
| R2               | assets + OCR documents         |
| WAF              | DDoS + bot protection          |
| Turnstile        | anti-abuse                     |
| Durable Objects  | optional realtime coordination |
| Queues           | lightweight async workloads    |
| Cron Triggers    | prewarming + scheduled tasks   |

---

## Why Cloudflare Is Central

Education workloads are:

* read-heavy,
* geographically distributed,
* highly repetitive,
* SEO-heavy,
* cache-friendly.

Cloudflare minimizes:

* backend round trips,
* latency,
* origin compute,
* egress costs.
