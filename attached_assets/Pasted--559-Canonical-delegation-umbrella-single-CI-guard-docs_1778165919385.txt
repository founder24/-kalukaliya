#559 - Canonical delegation umbrella — single CI guard + docs + ADR-0003 + cutover runbook
What & Why
After the six per-area wiring tasks (Sarvam Assamese chat, Azure OpenAI removal, voice paywall + narrowing, SES sole email, web push self-hosted, observability narrowing) ship the actual code changes, this umbrella task consolidates them into one authoritative source of truth:

One CI checker — scripts/ci/check_canonical_delegation.py replaces the per-provider scripts and enforces the entire map in one place.
One delegation doc — infra/four-cloud-delegation.md rewritten as a per-feature table mirroring the canonical map appendix.
One ADR — docs/architecture/adr/0003-canonical-strict-specialist-delegation.md documents the principles, the rejected providers and rationale, and the rollback procedure.
One cutover runbook — artifacts/syrabit/docs/infra/canonical-delegation-cutover.md documents the production cutover order, per-step verification, and per-step rollback.
This task is a strict dependent of all six per-area tasks — it cannot land until they have all merged. It contains no production code changes; it consolidates docs, CI guards, and the runbook.

E. New ADR-0003
docs/architecture/adr/0003-canonical-strict-specialist-delegation.md documents:

Context — why we moved from a multi-provider-per-feature world to one-provider-per-specialty.
Decision — the canonical map (full table embedded).
Principles — the five non-negotiables.
Removed providers + rationale — for each of Azure OpenAI, SendGrid, Resend, AssemblyAI, Deepgram TTS, Firebase Messaging, Sentry tracing, Cerebras, Cohere, Voyage-AI, Cartesia, Groq, OpenRouter, Quge5, AWS Bedrock, Supabase: a one-paragraph "why removed" + "what replaced it" + "rollback risk if we ever need to bring it back."
Alternatives considered — for the observability option (GlitchTip vs Sentry-free), the rejected option is documented here with its pros/cons.
Consequences — what gets harder under this map (no per-feature provider experimentation; provider-outage radius is wider since fallbacks are explicit), what gets easier (cost predictability, one mental model, one CI guard).
Reversibility — each removed provider's reintroduction cost in engineer-days.
F. Cutover runbook
artifacts/syrabit/docs/infra/canonical-delegation-cutover.md documents the production cutover order with per-step verification + rollback:

Step	Cutover action	Verification command	Rollback
1	Sarvam AI wired (task A merged)	curl /api/admin/health/sarvam returns ok	revert task A's PR
2	Assamese chat priority flip (task G locks chain)	Send Assamese test prompt; confirm Sarvam handled it	revert task A's PR
3	Remove Azure OpenAI (task B merged)	grep -r azure_openai returns zero	revert task B's PR
4	Voice paywall + narrowing (task C merged)	Free user gets 402; English/Assamese voice routes to right provider	revert task C's PR
5	SES sole email (task D merged)	Send synthetic transactional email; confirm SES delivery in us-east-1	revert task D's PR + restore SendGrid secret in KV
6	Web push migration kickoff (task E merged)	/api/push/vapid-public-key returns the public key	revert task E's PR (Service Worker auto-rolls back on update)
7	30-day push tombstone window	Daily admin-panel report shows ≥ 99 % migrated by day 30	extend window if < 95 %
8	Firebase project deletion (task E §E)	Firebase console shows project deleted; CI ban catches re-introduction	restore from Firebase project recycle bin within 30 days
9	Observability narrowing (task F merged)	/api/health/otel reports < 60s ingestion lag; GlitchTip/Sentry-free shows live errors	revert task F's PR + restore previous DSN
10	Land this CI checker + docs + ADR	CI checker passes on a no-op PR	n/a (docs + CI only)
Each step has a 7-day monitoring window with explicit alert thresholds (error rate not >2× baseline, p95 latency not >1.5× baseline, no new provider names in metrics.py). Any breach triggers automatic rollback to the previous git tag + Bicep revision.
