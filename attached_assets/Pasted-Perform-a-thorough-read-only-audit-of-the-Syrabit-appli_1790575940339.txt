SAFETY RULES — DO NOT VIOLATE
- Do not edit files, install packages, change workflows, create commits, deploy, or alter Cloudflare settings.
- Do not write to production D1, RAG, Vectorize, KV, R2, profiles, chat history, quotas, or other application state.
- Do not submit production chat prompts. Chat may reserve quota or persist conversations.
- Do not save profile changes, edit content, publish/unpublish chapters, reindex, or exercise staff write actions in production.
- Before calling a GET endpoint, inspect whether its handler writes to KV, warms a cache, logs a durable event, or otherwise mutates state. Do not call it if it has a write side effect unless that exact side effect has been explicitly approved.
- Do not translate, rewrite, or generate Assamese content. You may inspect availability flags and metadata, but do not expose private user data.
- Never print, copy, or request secrets, tokens, passwords, cookies, or credentials. Use approved integrations and secret-handling tools only.
- Do not bypass Cloudflare Access or authentication. If an approved authenticated account or safe test environment is unavailable, mark that flow “blocked/unverified” and continue with code review and safe public checks.
- Do not claim a feature is healthy merely because its endpoint returns 200, a workflow is green, or a page shell loads.

AUDIT METHOD
Use evidence from both:
A. Safe live checks that have no production write side effects.
B. Static review of the exact deployed GitHub SHA and its frontend/API contracts.

For every test, record the environment, deployed SHA if known, route or workflow, timestamp, expected result, actual result, and evidence. Compare production behavior with the exact deployed source. Separate findings into:
- Confirmed live
- Confirmed by deployed-source inspection, not safely testable live
- Suspected; needs additional evidence
